# 每次上游发送的 trace 观测

对应 issue #389。目标是回答一个候选 attempt 发了几次请求、每次如何失败、最终响应来自哪次发送，并保留每次发送的传输计时。

## 边界

复用 observed fetch 已有的 HTTP CLIENT span，不在 raw.invoke 或 SDK 回调处增加 span。候选 attempt 的上下文显式提供父 context；候选下标与从零开始的发送下标分开记录。现有协议路由和重试策略不变。

每次 fetch 建立独立观测，响应正文的读取闭包只更新这次发送。响应头、首字节、首个 SSE 事件、编码、每次读取的帧数均相对该发送起点。未经控制的自动解压路径只记响应头和正文终态，不把解码后的读取冒充线上字节。

HTTP span 的结束时间是异常、正文完成或取消的时刻；未消费正文的发送使用最后已知时刻。span 暂存至 attempt 结算，以便写入 raw 协议重写原因和最终响应来源，再在父 span 结束前统一结束。没有 attempt 的 fetch 保持原来的响应头结束边界。

## 响应来源

用 WeakMap 关联响应对象与发送观测；raw SSE preflight 包装响应时传递关联。成功重写后标记原发送为协议拒绝，包含 HTTP 200 SSE 错误帧的情况。raw 最终响应使用对象关联；SDK 实际输出内容或成功结算时，只关联唯一已消费且未被协议重写替换的 2xx 响应，因此仅返回工具调用的成功响应也能关联来源。正文之后失败或取消不抹掉已输出内容的来源；未输出内容便失败或取消的旧响应不参与后续输出归因。存在多个可能来源时不猜测；未输出内容且结算失败时不推断 SDK 响应来源。

旧 attempt 聚合字段保留兼容语义，包括 ambiguous；新发送 span 不受聚合歧义抑制。dashboard 明确解释历史多响应情况，显示发送序号、实际发送次数、最终响应发送序号，以及发送自己的传输计时。发送 span 不计为候选 attempt。

## 容量与隐私

不增加每个 fetch 的 span 数量。每次发送额外保存固定大小的标量和一个结束回调，不复制正文、不建立逐帧列表、不建立内容间隔直方图。状态在 attempt 结算后释放。URL 脱敏、敏感请求属性白名单保持现有策略。

## 验证

覆盖两次响应各自保留计时、抛异常后重试、交错消费不串数据、正文错误/取消、未消费正文结算、raw 400 重写与 200 SSE 拒绝、SDK 自身重试、来源不明确不误归因、敏感请求脱敏，以及 dashboard 不把发送计入 attempt 数量。
